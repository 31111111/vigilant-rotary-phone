# 视觉引导机械臂（OpenCV + 手眼标定 + 两连杆 IK）

一个**纯 PC、无需硬件、无需 PyBullet** 即可运行的 eye-to-hand 视觉引导抓取项目：
俯视相机渲染桌面场景，OpenCV 识别彩色目标，手眼标定把像素坐标转成机械臂基坐标，
平面两连杆逆运动学解算关节角，驱动机械臂完成“对准 → 下探 → 夹取 → 搬运 → 释放”
完整闭环，并对全链路误差做蒙特卡洛量化。

> 设计为可独立运行的“数字孪生 / 合成数据”验证环境：算法先在仿真里跑通、量化误差，
> 再迁移到真实摄像头与机械臂。视觉模块对真实摄像头接口完全一致（见文末迁移说明）。

## 一、系统数据流

```
scene.render()  俯视相机渲染（真实内参：尺度/主点/旋转 + 传感器噪声）
      │ BGR 图像
      ▼
vision.detect() BGR→HSV 颜色分割 → 形态学开闭运算 → 轮廓检测
      │           图像矩求中心、最小外接旋转矩形求尺寸/朝向
      ▼
calibration     121 点标定板拟合 像素→世界 变换（相似/仿射/单应）
      │           输出目标世界坐标 (x, y)，单位米
      ▼
arm_kinematics  底座旋转 φ + 平面两连杆 IK（余弦定理，含可达性/肘分支）
      │
      ▼
main 动作序列   逐帧动画 + 夹爪开合 + 目标跟随，合成 mp4
```

## 二、文件结构

| 文件 | 职责 |
|---|---|
| `scene.py` | 俯视相机模型与场景渲染（相机地面真值、方块、网格、噪声） |
| `vision.py` | OpenCV 识别：HSV 分割、形态学、轮廓、矩、最小外接矩形 |
| `calibration.py` | 手眼标定：最小二乘相似变换 + `estimateAffine2D` + `findHomography` |
| `arm_kinematics.py` | 平面两连杆逆/正运动学、关节插值 |
| `main.py` | 视觉引导抓取闭环，输出视频与指标 |
| `error_analysis.py` | 100 次蒙特卡洛误差统计与图表 |
| `requirements.txt` | 依赖清单 |
| `output/` | 运行产物：标注图、JSON 指标、误差图 |

## 三、安装与运行

## 四、核心原理（复试考点）

1. **HSV 颜色分割**：相比 RGB，HSV 把色调 H 与亮度 V 分离，对光照变化更鲁棒；
   红色在 H 通道跨 0/180，用两个区间。
2. **形态学滤波**：开运算（先腐蚀后膨胀）去椒盐噪点，闭运算（先膨胀后腐蚀）填内部孔洞。
3. **中心与朝向**：用图像矩 `M` 求质心 `(m10/m00, m01/m00)`；`minAreaRect` 给旋转矩形与角度。
4. **手眼标定（eye-to-hand）**：相机固定在工作区外，标定板角点提供“像素 ↔ 世界”对应点，
   最小二乘求解变换矩阵；用重投影误差评估标定质量。
5. **平面两连杆 IK**：底座先转方位角 `φ=atan2(y,x)`，再用余弦定理求肘角
   `cos θ2=(r²−L1²−L2²)/(2L1L2)`，进而求肩角；`r` 超出 `[|L1−L2|, L1+L2]` 即不可达。

## 五、实验结果

**手眼标定（121 点）**：内参估计几乎完全还原真值——尺度 749.7 vs 750 px/m、
旋转 −8.000° vs −8.000°、主点精确命中；世界坐标重投影误差平均 **0.43 mm**。

**闭环抓取**：视觉定位/抓取对准误差 **0.67 mm**，放置落点误差 0，138 帧。

**蒙特卡洛 100 个随机目标**：

| 指标 | 均值 | P95 | 最大 |
|---|---|---|---|
| 识别中心像素误差 (px) | 0.75 | 1.03 | 1.08 |
| 视觉定位世界误差 (mm) | 0.95 | 1.34 | 1.49 |
| 标定重投影 (mm) | 0.43 | — | 1.37 |

误差在工作区内无明显空间偏向，说明主要来自随机传感器/角点噪声，无系统性残差。

## 六、复试高频问答

**Q：为什么用 HSV 而不是直接在 RGB 里分割？**
A：RGB 三通道都耦合亮度，光照一变阈值就失效；HSV 把色调和亮度分开，固定 H/S 区间
对光照变化更鲁棒。

**Q：红色为什么要单独处理？**
A：H 是环形量，红色位于 0°（也是 180°）两端，单区间会漏掉，需要 0–10 与 170–179
两段掩码取并集。

**Q：手眼标定 eye-to-hand 和 eye-in-hand 区别？**
A：eye-to-hand 相机固定在环境中、不随末端运动，标定相机到机械臂基座的固定变换；
eye-in-hand 相机装在末端随动，需要标定相机到末端法兰的变换。本项目是前者。

**Q：标定误差来源有哪些？**
A：角点亚像素检测误差、镜头畸变、标定板平面度、机械臂与相机的相对安装误差。
本项目用重投影误差量化，并通过多取点（121 个）做最小二乘抑制随机误差。

**Q：两连杆什么时候无解？**
A：目标水平距离 r 超出 `[|L1−L2|, L1+L2|]` 时余弦定理越界，对应工作半径外，
代码里先做可达性判断再求解。

**Q：怎么证明你的结果可信？**
A：相机参数是已知地面真值，可直接对比；`error_analysis.py` 用 100 个随机点重复完整链路，
给出均值/P95/最大误差，所有数字可复现。

## 七、迁移到真实硬件

- **真实摄像头**：把 `scene.render()` 换成 `cv2.VideoCapture(0).read()`，后续 `vision.detect`
  及之后代码无需改动；用真实棋盘格（`cv2.findChessboardCorners`）替换模拟标定板。
- **真实机械臂**：把 `arm_kinematics` 的关节角通过串口/ROS 下发给舵机或控制器，
  夹爪开合映射到舵机 PWM；建议先做相机内参标定（`cv2.calibrateCamera`）校正镜头畸变。
- **更鲁棒的感知**：可把颜色分割升级为 ArUco 标记或目标检测网络，标定与 IK 链路保持不变。
